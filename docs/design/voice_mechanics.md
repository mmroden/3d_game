# Voice Mechanics — audio, subtitles, recording, garble

Design proposal for Mark's 2026-08-30 asks: (1) audio and/or on-screen text
for script lines, (2) voice audio as pipeline assets, (3) a way to record
the takes, (4) a transform chain on the Other's lines whose intensity
attenuates as the player progresses. Engineering only — no plot content.
Nothing below is implemented; decisions D1–D6 at the bottom are yours.

## What exists today (verified 2026-08-31)

- Buses `Master` / `Music` / `SFX` in [default_bus_layout.tres](../../godot/default_bus_layout.tres).
- `AudioManager` — Rust GDExtension class in the main scene: phase-driven
  music with two crossfade players, `play_sfx_event(_at)`, polyphony +
  collision throttling. GUT contracts in [test_audio.gd](../../godot/tests/test_audio.gd).
- Audio assets already ride Door 1: `assets/music` + `assets/sfx` →
  `scripts/install-addons.sh` → `godot/addons/audio/{music,sfx}` under
  stable names; `assets-probe` regenerates `catalog/*.generated.toml`.
- Precedent for authored game data: `rosters/` TOML grammar (open-set,
  template + vocabulary regenerated by build).

Voice extends each of these doors. No new parallel systems.

## 1. Line data — `voice/lines.toml`

The script markdown (script/02_run_one.md …) stays the *drafting/redline
surface*. Once a line is approved it is entered in a `voice/` TOML grammar —
the single truth the game loads (same move as rosters/: the TOML **is** the
game data):

```toml
[line.C-07]
speaker = "control"          # control | other
class   = "pool"             # pool | once  (once = plays once per save)
trigger = "rtb_order"        # open-set trigger name; shell wires events to it
text    = "That's enough for one day. Abort tasking. RTB, best speed — we sort the charts on the ground."

[line.O-11]
speaker = "other"
class   = "once"
trigger = "idle_long"
text    = "[CALLSIGN]."
garble  = { mode = "offset", value = -0.6 }   # script demands this one nearly clean
```

- `garble` defaults to `auto` (campaign value, §4); `fixed`/`offset` exist
  because the script already requires per-line exceptions (O-11's "no hiss").
- `[CALLSIGN]` stays a token in data; substituted at display/record time
  once you pick one.
- Tests derive from the grammar, never pin content (no-data-pins): IDs
  unique, speaker in vocabulary, text non-empty, every `trigger` reachable
  from the shell's wiring table.

## 2. Audio assets — the same three doors

- **Source:** `assets/voice/takes/<LINE-ID>.wav` — your recordings, named
  by line ID. That naming contract is the whole recording interface.
- **Door 1 (install):** `install-addons.sh` gains a voice stage: loudness
  normalize + silence-trim + encode → `godot/addons/audio/voice/<ID>.ogg`.
  Mastering lives in the pipeline, not in your takes.
- **Temp VO:** for any line in `voice/lines.toml` with no take, the install
  stage synthesizes one (macOS `say` → encode), flagged `temp = true` in
  the census. The entire system — triggers, subtitles, garble, mixing — is
  buildable and playtestable before you record a single word, and each real
  take replaces its temp render with zero further changes (guide step 5's
  temp-VO idea, now mechanical).
- **Door 3 (probe):** census → `catalog/voice.generated.toml`: every line
  ↔ exactly one installed file, orphan files fail, temp/real counts
  reported. `test-assets` (pytest) audits conservation like materials.

## 3. Playback + text on screen

- **Buses:** add `VoiceControl` and `VoiceOther` (→ Master). The Other's
  transform chain lives on `VoiceOther` (§4), so it applies uniformly and
  is tunable live in the editor.
- **AudioManager** grows `play_voice_line(id)`: one dedicated
  `AudioStreamPlayer` per bus, created at ready — no per-line allocation
  (faucet-compliant), one line playing per channel, interrupt policy =
  newer once-class beats pool-class, nothing queues more than one deep.
- **Trigger wiring:** the shell's existing event/broadcast path (the same
  fabric that feeds `on_phase_changed_audio`) maps game events → trigger
  names → line selection (once-lines first, else weighted pool, no repeat
  within a run). Selection policy is shell code with GUT contracts; line
  content stays data.
- **Subtitles — out of the screen (Mark, 2026-08-31, "like the credits in
  Prometheus"):** not flat HUD. The entire 2D UI layer renders onto one
  quad at a fixed distance in SBS (ViewManager's UIPlane, 10 m), so a
  caption there is glued to that plane — wrong tool for pop-out. Instead
  each line renders as world-space 3D text (Label3D: billboarded,
  no-depth-test so a wall never eats a line, outlined for contrast)
  anchored to the camera rig at lower-center of the fused view. A real
  object in front of both eye cameras gets correct SBS parallax for free —
  it comes out of the screen exactly as far as we place it — and the same
  node works untouched in mono. Its depth is a client of the stereo
  director: a rung at, or a touch inside, current convergence (modest
  pop-out; the established near-plane-at-2m-is-nausea finding bounds how
  far out it may come), and it follows convergence rather than driving
  it — the deleted reticle's lesson: the converged plane is the look-here
  signal, and subtitles must not hijack it. Text-only delivery before
  audio exists comes free ("and/or text").
- **Speaker tagging is a plot decision (D5):** distinct tags ("CONTROL:" /
  "???:") would spoil the same-voice conceit early. Options: no tag /
  uniform tag ("COMMS") / distinct. The mechanics support any.

## 4. The garble transform and its attenuation

One scalar **g ∈ [0,1]** — garble intensity for the Other. Single source of
truth: derived from persisted meta-progress in game logic and broadcast the
same way GameOptions reaches consumers; AudioManager and the subtitle
renderer both consume it, neither computes it.

- **What drives g down (D2):** "as the player plays further" — candidate
  metrics: furthest planet reached / bosses (launchers) killed / total
  runs. The mapping is an authored curve in `voice/` data, not code, so
  tuning never touches tests.
- **The chain on `VoiceOther`** (Godot built-in effects, in series; every
  parameter is a function of g):
  | element | effect | at g=1 | at g→0 |
  |---|---|---|---|
  | dropouts | scripted gate in AudioManager (no built-in): seeded on/off mask, deterministic per (line, g-bucket) | ~60% masked — fragments ("—urn— —turn—") | off |
  | radio squeeze | AudioEffectBandLimitFilter/EQ | narrowband | full band |
  | crush | AudioEffectDistortion (lofi) | heavy | off |
  | identity mask | AudioEffectPitchShift, small offset | enough that the voice can't be clocked as Control's | **first to reach zero** — the voice becomes recognizable before it becomes clean |
  | noise bed | looping noise stream on the bus, volume ∝ g | prominent | silent |
- The dropout mask is why "record clean, garble in post" holds: your take
  is untouched; the fragments the script writes as *heard-as* renders are
  the gate's output, reproducible in tests because the mask is seeded.
- **Text mirrors audio:** the subtitle for an Other line is masked by the
  same seeded pattern at the same g (characters/words blanked), one pure
  function in game logic — property-tested (mask fraction monotone in g,
  deterministic, zero at g=0). Deaf players get the same arc.
- Control's lines: no chain (his erosion is performance, not signal — your
  spec). `VoiceControl` exists so a later decision *could* add one without
  rewiring.

## 5. Recording — your side of the contract

- Minimum viable: record in anything (QuickTime/Audacity), export
  `<LINE-ID>.wav` into `assets/voice/takes/`, run `make assets`. Census
  tells you coverage (real vs temp) after every pass.
- Offered increment (D6): `make voice-record` — a terminal teleprompter
  over `voice/lines.toml`: shows line + VA note from the script doc,
  space to record/stop (pyenv + sounddevice), instant replay, retake,
  auto-naming. Worth it around the time line count crosses ~50; the naming
  contract above works day one without it.

## 6. TDD shape (red first, per piece)

- **Rust (void_logic):** voice grammar round-trip + template/vocab
  regeneration (rosters pattern); census conservation (line↔file, orphan
  detection); g-curve evaluation; text-mask properties. No pinned line
  content anywhere.
- **GUT (shell contracts):** VoiceControl/VoiceOther buses exist and route
  to Master; AudioManager exposes `play_voice_line`; playing an Other line
  sets chain parameters per broadcast g; the subtitle Label3D exists under
  the camera rig, is populated on play, and sits at a depth the stereo
  director owns; once-class line refuses a second play in the same save.
- **pytest (pipeline):** install stage normalizes/encodes; temp-VO fills
  gaps and flags them; re-run idempotent.

## Decisions for Mark

- **D1 — runtime chain vs baked tiers.** Above recommends runtime bus
  effects (continuous attenuation — your "slowly attenuated" — one clean
  asset per line, live-tunable). Alternative: pipeline pre-renders N garble
  tiers per line (zero runtime DSP, coarse steps, re-render to tune).
  **Rec: runtime.**
- **D2 — what advances clarity:** furthest-planet / launcher kills / runs
  completed (+ authored curve). **Rec: furthest-planet reached, smoothed —
  matches "as the player plays further."**
- **D3 — where line data lives:** new top-level `voice/` grammar dir
  (rosters-style). **Rec: yes; script md stays the redline surface.**
- **D4 — temp VO via `say`** so mechanics ship before recording sessions.
  **Rec: yes; census keeps temp/real honest.**
- **D5 — subtitle speaker tagging:** none / uniform "COMMS" / distinct.
  Plot-relevant (the reveal). **Rec: uniform.**
- **D6 — teleprompter recorder:** build now, later, or never (naming
  contract suffices). **Rec: later, once registers lock and line count
  grows.**

Increments if approved (effort→value, no ordering constraint beyond the
first): ① grammar + census + temp-VO through the three doors; ② buses +
`play_voice_line` + subtitles; ③ garble chain + g broadcast + text mask;
④ trigger wiring for run-one's line set; ⑤ teleprompter.
